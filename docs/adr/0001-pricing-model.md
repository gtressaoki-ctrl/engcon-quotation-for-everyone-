# ADR-0001: 価格計算体系（掛け率・丸め・税・運賃）

- Status: Accepted
- 日付: 2026-07-05（実装は 2026-06 時点で稼働中。本 ADR は判断の明文化）
- 実装: `lib/pricing.ts`

## Context
G.TRES は engcon 製品を定価（price_master.price_jpy）ベースで仕入れ、
顧客区分ごとに異なる掛け率で販売する。掛け率は G.TRES の商流上の取り決めであり、
アプリ側の都合で変えてよい数値ではない。

## Decision
価格種別（price_type）と計算式を以下に固定する：

| price_type | 対象 | 計算式 |
|---|---|---|
| dealer | 登録ディーラー向け | 定価 × 0.75 × 1.1 |
| enduser | エンドユーザー・その他 | 定価 × 0.75 × 1.2 |
| reseller | 未登録販売店 | 定価 × 入力掛け率%（見積ごとに入力、未入力時 85%） |
| rsm | RSM（client_name に "RSM" を含む dealer） | 定価 × 0.8125（③弊社からの卸） |

- RSM 見積には参考値として「御客様販売単価」= 定価 × 0.875（④RSM の卸）を併記する
- 商流の段階：①定価 → ②弊社の仕入（75%）→ ③弊社からの卸（81.25%）→ ④RSM の卸（87.5%）
- 丸め（roundPrice）：計算後の単価が 10,000 円以上なら千円単位、未満なら百円単位で四捨五入
- 金額 = 丸め後単価 × 数量（単価手修正時は roundPrice(単価×数量)）
- 運賃 = パレット数 × 35,000 円（save-quote がサーバー側でも同式で再計算して保存）
- 消費税 = 小計 × 10% の **floor**（切り捨て）

## Rejected alternatives
- **掛け率を DB（設定テーブル）に持つ**：値の変更頻度が極めて低く、変更は商流の再交渉を
  意味する重大イベント。DB 化すると「うっかり変更」の経路が増えるため、コード内定数 +
  ADR + テストで固定する方を採った
- **税・丸めを共通ユーティリティライブラリに委譲**：計算仕様（floor、千円/百円境界）が
  日本の商慣習・G.TRES の見積書式に固有のため、自前の 50 行で持つ方が明確

## Consequences
- 掛け率変更 = 本 ADR の改訂 + `lib/pricing.ts` + `lib/pricing.test.ts` の同時変更（ユーザー承認必須）
- reseller の掛け率だけはユーザー入力値なので、UI（Step2）とストアの `reseller_rate` が連動する
- getPriceType の判定順序（RSM 最優先）を変えると既存見積と価格が変わるため変更禁止
